# 카트 레이스 🏎️

위에서 내려다본 서킷을 3바퀴 달리는 카트 경주입니다. 서버 없이 `index.html` 만 열면 돌아갑니다. 카트라이더처럼 **드리프트로 부스터**를 모으고 **아이템 상자**를 씁니다.

- 조작(폰): 왼쪽 아래 **◀ ▶** 로 핸들, 오른쪽 아래 **드리프트**(누르고 있기)와 **아이템** 버튼. 가속은 자동입니다.
- 조작(PC): `←` `→`(또는 A D) 핸들, `Space`·`Shift`·`Z` 드리프트, `X`·`↑`·`Enter` 아이템, `↓` 브레이크, `P` 일시정지, `M` 소리. 창이 가려지면 저절로 일시정지합니다.
- 규칙은 `logic.js`(DOM 없음), 화면·소리·입력은 `game.js`. 시험: `node --test`.

## 규칙
- 코스 3곳(초원 서킷 · 산길 S · 도심 헤어핀), 3바퀴. 컴퓨터 카트는 쉬움 5대 · 보통 7대. 3·2·1 신호 뒤 출발, 결승선을 넘은 순서가 순위입니다(내가 들어온 뒤 12초가 지나면 끝나고, 못 들어온 카트는 달린 거리 순).
- **드리프트**: 빠를 때(최고 속도의 55% 이상) 핸들을 꺾고 드리프트 버튼을 누르면 미끄러집니다. 계속 누르면 게이지가 차고(0.7초 · 1.4초 · 2.2초에 1·2·3단계), **버튼을 놓으면** 단계에 따라 0.7 · 1.1 · 1.6초 **부스터**가 터집니다. 안쪽으로 꺾으면 급하게 돌고 반대로 꺾으면 펴집니다. 벽에 부딪히면 취소됩니다.
- **풀밭**은 속도가 절반이고, 그 바깥 **수풀 벽**은 넘어갈 수 없습니다. 2.6초 넘게 못 움직이면 길 한가운데로 옮겨 줍니다. 거꾸로 달리면 경고가 뜹니다.
- **아이템 상자**(? 상자, 먹으면 4초 뒤 다시 나타남): ⚡ 부스터(1.6초) · 🍌 바나나(뒤에 놓음, 밟으면 1초 미끄러짐) · 🚀 로켓(앞으로 날아가 가까운 카트를 살짝 쫓아가 맞춤, 1.3초 스핀) · 🛡️ 방어막(8초, 공격 한 번 막음). **순위가 낮을수록 부스터·로켓**, 높을수록 바나나·방어막이 잘 나옵니다.
- **난이도**: 「쉬움」은 컴퓨터가 84% 속도에 드리프트를 안 쓰고 실수도 잦습니다. 「보통」은 92% 속도로 커브에서 드리프트 부스터를 씁니다. 컴퓨터는 앞서면 조금 느려지고 뒤처지면 조금 빨라집니다(±5~7%). **보통에서 1등 한 횟수**가 기록(`kartraceWins`)입니다.

## 균형을 어떻게 맞췄나
- 코스는 길이(약 5300 · 5900 · 6850), 길이 서로 겹치지 않는 간격, 가장 급한 커브 반지름을 시험으로 검사합니다(`node --test`).
- 컴퓨터끼리 전 코스를 돌려 보고(쉬움 · 보통 6판) 모두 완주하는지, 길을 못 벗어나는지, 한 판이 약 70~105초인지 확인했습니다.
- 「나」 자리에 같은 운전 봇을 넣어 36판씩 모의: 드리프트를 쓰는 봇(실력자) 보통에서 속도 100% 일 때 1등 약 80%, 93% 일 때 약 20%(평균 3.3등). 드리프트를 안 쓰는 봇은 보통에서 평균 3.2등(100%) ~ 5.3등(93%). 쉬움은 93% 속도에서도 거의 1등. 즉 **보통은 드리프트를 익혀야 1등**을 할 수 있게 맞췄습니다.
- **사람의 실제 체감 난이도와 폰 조작감은 측정하지 못했습니다.**

## 참고한 것과 제가 정한 값
- 「위에서 본 카트 경주 + 드리프트 부스터 + 아이템」이라는 널리 알려진 형식을 따랐습니다. 코스 모양, 속도, 드리프트 시간, 아이템 효과 수치는 모두 제가 정한 값입니다. 온라인 대전은 아직 없습니다.
